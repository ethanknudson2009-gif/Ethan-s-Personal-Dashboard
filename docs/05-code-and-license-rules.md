# 05 — Code & License Rules

**Confirmed: we do not copy or paraphrase any code from any repo or app.** We take *ideas* only, and every line of this dashboard is written fresh.

1. **Ideas, not code.** We study what an app or repo *does* (its features, workflows and screens) and write it down in our own words. Ideas and features aren't owned by anyone; specific code is.
2. **Clean-room build.** Code is written from *our* spec (docs 01–04 and 06), not from anyone's source files. Nobody opens another project's code "to paraphrase it," because rewriting code line by line can still count as copying.
3. **No code is ever copied.** The only thing we may reuse directly is **public-domain data** (not code) with zero strings attached (Unlicense, CC0), such as the free-exercise-db exercise list. MIT/BSD/Apache projects still require keeping their copyright notice, so we don't copy from them either.
4. **Never** use GPL, AGPL, MPL, non-commercial (CC BY-NC) or unlicensed code, not even paraphrased.
5. **Standard building blocks are installed, not copied.** Normal libraries (Next.js, React, the Supabase client, a calendar component) are added as npm packages, the way every website is built. Their license notices travel with them automatically.
6. **Data sources are credited where required**, e.g. "Food data from Open Food Facts."

*Not legal advice. This is a cautious, standard approach for a school project.*
